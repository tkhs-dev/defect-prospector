# 要求仕様書 — defect-prospector

## 1. プロジェクト概要

機械学習・静的解析研究向けのバグデータセットを構築するため、複数のリポジトリ・課題管理システムからバグ情報を収集・整形するツール群を開発する。

## 2. 用語定義

| 用語 | 定義 |
|------|------|
| バグレコード | 1件のバグを表すデータ単位。Issue情報・VCS情報・再現情報を含む |
| バグ状態 | バグが存在するコミット時点のリポジトリスナップショット |
| 修正状態 | バグが修正されたコミット時点のリポジトリスナップショット |
| アダプタ | 特定の外部システム（VCS、課題管理、言語）との通信を抽象化するモジュール |

## 3. 機能要求

### 3.1 バグ情報の収集

- **FR-01** 課題管理システムからバグ種別のIssueを検索・取得できること
- **FR-02** 取得したIssueに紐付くVCSのコミット（バグ混入コミット・修正コミット）を特定できること
- **FR-03** バグ再現に十分な情報（環境情報・再現手順・差分）をセットで収集・保存できること
- **FR-04** ラベル・重要度など、Issue の補助情報も収集できること

### 3.2 アダプタ拡張性

- **FR-05** VCSアダプタを追加することで Git / SVN / Mercurial 等に対応できること
- **FR-06** 課題管理アダプタを追加することで GitHub Issues / GitLab Issues / Jira / Bugzilla 等に対応できること
- **FR-07** 言語アダプタを追加することで Python / Java / JavaScript 等の言語固有情報を取得できること
- **FR-08** アダプタはコア機能を変更せずに追加（プラグイン的に差し込む）できること

### 3.3 チェックアウト機能

- **FR-09** バグIDを指定してバグ状態（修正前）のコードをチェックアウトできること
- **FR-10** バグIDを指定して修正状態（修正後）のコードをチェックアウトできること
- **FR-11** チェックアウト先ディレクトリを任意に指定できること

### 3.4 データ管理・エクスポート

- **FR-12** 収集済みバグレコードを一覧表示できること
- **FR-13** バグIDを指定して詳細情報を表示できること
- **FR-14** データセットを JSON / CSV / Parquet 形式でエクスポートできること
- **FR-15** フィルタ条件（言語・重要度・日付範囲など）を指定して絞り込みエクスポートできること

## 4. 非機能要求

### 4.1 可搬性・移植性

- **NFR-01** Python 3.10 以上で動作すること
- **NFR-02** OSはLinux / macOS / Windows（WSL含む）で動作すること
- **NFR-03** アダプタは独立したモジュールとして実装し、コアへの依存を最小化すること

### 4.2 信頼性

- **NFR-04** ネットワークエラー・API Rate Limit に対してリトライ処理を行うこと
- **NFR-05** 収集途中で中断した場合、再開できること（べき等な収集処理）

### 4.3 セキュリティ

- **NFR-06** APIトークン等の認証情報は設定ファイルまたは環境変数で管理し、コードに埋め込まないこと

### 4.4 保守性

- **NFR-07** アダプタインターフェースは安定したABCとして定義し、後方互換性を保つこと
- **NFR-08** 各アダプタは独立してテスト可能であること

## 5. 対象外

- バグの自動分類・優先付け
- 修正パッチの自動生成
- リアルタイム監視（バッチ収集のみ）
